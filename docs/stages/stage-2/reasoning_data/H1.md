## 4. H1: the comparison (`plans/comparison_design.json`, a draft)

**Question.** With the same D4 initialization, the same recovery objective and
a pre-defined matched budget, does replacing corpus_v2 with a verified
teacher-native reasoning corpus improve *actual reasoning correctness* in the
student's own generations?

It is a treatment comparison of two whole data schemes, not a test of a single
filter.

**Arm A: corpus_v2 as it was.**
- The only change is isolation: 28 sessions are dropped as near-copies of
  held-out prompts.
- It is **not cleaned**: its wrong targets remain, as they were historically.
- Measured: 3,151 units, 2,962,295 U, 1,460 blocks at 0.355 packing
  efficiency.
- No E1 result stands in for it, because E1 used a PCA initialization and a
  pack that cut traces.

**Arm B: the verified teacher-native corpus.**
- Shares of unique supervised positions: reasoning **0.70** / supporting
  **0.30**, the maintainer's starting point and not a searched optimum.
  - deduction 0.17, induction 0.17, composition 0.17, analogy 0.09,
    interactive 0.10;
  - math 0.12 (0.06 reused verified gsm8k + 0.06 new MATH train), code 0.07,
    evidence reading 0.08 (reused span-verified), answerability 0.03.
- Instruction following is exercised by every task's explicit answer or action
  protocol. Tool calling is omitted. Both are recorded risks.
- **Estimated independent units at 2.96M** (`h1_accounting.json :: quotas_arm_B`):

  | stratum | units |
  | --- | --- |
  | deduction | 136 |
  | induction | 137 |
  | composition | 141 |
  | analogy | 46 |
  | **interactive episodes** | **18** (thin, so the axis is secondary) |
  | reused gsm8k | 151 |
  | MATH | 52 |
  | code | 49 |
  | reading | 380 |
  | answerability | 174 |

- **Families.** The project generators give 35 calibration-split families. The
  §8 sources add about 23 mechanisms (Reasoning Gym about 15, Reasoning Core 7,
  PrOntoQA 1) if approved, none of which is an eval-set-1 mechanism.

**Quality** (`target_quality` + process checks).
- Every candidate keeps its ending, protocol, answer and process states apart.
- The answer is verified against an independent gold: the generator's gold,
  the human math gold, test execution (`aadistill.data.code_exec`), or the
  span gold.
- **Process states:**
  - `verified`: an episode replays with every action legal;
  - `partial`: the final answer is derived inside the reasoning; a quoted
    prompt format example does not count;
  - `contradicted`: rejected;
  - `not_assessed`: the honest default for anything else.
- **On the Stage-0 teacher records:** 571 of 672 accepted. Of the static
  answer-correct traces, 497 are `partial` and 58 `not_assessed`; 68 episodes
  are `verified` and 4 `contradicted`.
- A sampled independent review per family is part of the protocol.
- Ambiguity and solvability are guaranteed by the generators' construction:
  - induction keeps an instance only when every rule in its library that is
    consistent with the examples agrees on the query;
  - deduction redraws unsatisfiable seeds;
  - training uses the audited v2 roster.

**Isolation.** Rules R1–R8 cover:
- held-out keys;
- 13-gram near-duplicates;
- rule families;
- evaluation-only generators *and their task types*;
- shared-generator seed range;
- source splits;
- ARC.

`train_tasks_v1` (2,517 tasks) passes R1–R6 and repeats no Stage-0 or eval
instance.

**Matched budget** (`h1_accounting.json`). M1 is the primary basis:
- **U** equal within 1%: measured ratio 1.0008;
- **E** equal over 3 epochs: 1.0013;
- **optimizer steps** equal within 10%: 1.0032, with arm A at 7 blocks per
  step against B's 2, so supervised positions per step match (0.998);
- **C is not matched:** A executes 1.28× the positions and 1.22× the FLOPs,
  because its prompts are context;
- `truncate_padding` is on in both arms, as one versioned data profile
  (`h1_pack_profile@v1`).

Under the frozen config, A would get 3.5× the steps and compute at 0.29× the
supervision per step.

**Schedule.** Registered from B's real pack: T ≈ 624, warm-up 31, eval every
78, save every 312. The 0.86M recipe's 1,023 steps are not reused.

**Counting rules:**
- one trace per task;
- repeated context is computed, never counted in U;
- reasoning and answer positions are reported separately.

**Recovery: frozen.**
- CE 0.25 + KD 1.0, T = 1, `kd_scope: all`, full-vocabulary forward KL.
- Same trainable set, AdamW 5e-5, fp32 + bf16 autocast, thinking protocol and
  8,192 context.
- Not introduced: TIP, another KL direction, top-k KD (D1's Top-200 is an
  initialization scoring protocol), hidden or span alignment, loss
  reweighting, student-forced or on-policy training.

**Evaluation.** Uses eval-set-1, frozen identity 2.
- Reported, each separately: every fluid axis; episodes; **both generator
  tiers** (unseen format 190 + 48; unseen rule 380 + 96); supporting units;
  guard rails; usable rollout and its components; CE and KL as diagnostics.
- Diagnostic chain: usable → submitted in protocol → correct → correct on the
  unseen-format tier. The first two alone are not transfer.

**Statistics, fixed before any result is read.**
- **Primary:** static correctness B − A, item-paired within seed and pooled.
- **Interval:** rule-family cluster bootstrap that never splits an equivalence
  group (`independence_v1.json`).
- **SESOI:** 0.05 (0.08 per axis).
- **Labels:** GO = interval wholly above +0.05 *and* both seeds above it;
  otherwise NO-GO, REVERSED, INCONCLUSIVE or FLOOR.
- Axis contrasts are Holm-adjusted; the rest is descriptive.

**Steps.** All four formal units run once launched. A single-seed diagnostic
is allowed but is not a confirmation. If B is fully at the floor after
reasonable diagnostics, the next study is H3, not a larger ladder.

## 7. H3 candidate: TIP (`plans/h3_candidates.json`)

**Reference.** *TIP: Token Importance in On-Policy Distillation*,
arXiv:2604.14084, v4 (2026-05-21). Only the abstract has been read.

**What it does.** It selects tokens by student entropy combined with
teacher–student divergence, including low-entropy/high-divergence positions,
on student rollouts.

**Status.**
- Registered as a research direction.
- **Not in the H1 trainer.**
- Not implemented, not scheduled, not funded.

**Rules for any future study.**
- The faithful method is on-policy (Stage 4/5 ownership).
- An offline forward-KL variant would be a "TIP-inspired adaptation".
- A study would vary trajectory distribution, KL direction and selection rule
  one at a time, against an all-token arm with the same trajectories and the
  same KL.

## 8. Data sources: the executable source table

**Machine-readable rows.**
- `configs/stages/stage-2/reasoning_data/external_modules.json`: one row per
  module, with stratum, task type, verification, isolation and decision;
- `sources.json`: the sources;
- `corpus_spec.json :: source_allocation`: each stratum's share split by
  source.

**What the audit rests on.** A primary-source desk check of all 8 repos, plus
a $0 local validation of 5 instances per module per difficulty from pinned
installs in an isolated scratch environment.
- **Isolation:** the 305 sampled candidate instances pass R1 and R2 against
  eval-set-1, with 0 key overlaps and 0 13-gram near-duplicates
  (`audit/external_source_samples.json`).
- **Code verifier:** calibrated on MBPP's human reference solutions. It passes
  473/474, and rejects 453 of 474 "return None" mutants
  (`audit/code_verifier_check.json`).

**Policies that apply to every external source:**
- **A library score is never the verdict.**
  - Wrong answers score 0.84–0.999 in several Reasoning Gym modules.
  - Five Reasoning Gym scorers evaluate the answer text as Python, so they
    never see teacher output.
  - Each module therefore gets a project-side exact or validity check.
- **Instances are generated once and stored.** PYTHONHASHSEED and every seed
  are pinned, in a fresh process per module. Several generators depend on the
  hash seed, the global RNG, process history or the wall clock, so nothing is
  regenerated later.
- **Reference proofs and traces only verify.** They never enter a prompt or a
  target, and the external answers are never the teacher's target.

**Counting rules.**
- One mechanism found in two libraries counts as one family.
- Several teacher traces of one prompt count as one task.
- Static planning (Reasoning Core `planning`, Reasoning Gym sokoban /
  rush_hour) is never counted as interactive.

**Interactive coverage is insufficient, and is reported rather than filled.**
- The only interactive training source is the project's own environments:
  hidden_buttons (1 calibration family) and probe_function (2).
- That is 3 families, about 18 accepted episodes at 2.96M.
- No external source supplies a real action → observation → feedback loop.
- New seeds cannot turn evaluation families into training ones.
- Closing the gap needs new training-only environments: $0 engineering, and a
  maintainer decision.

**Fallback.** If a third-party generator is not approved, its allocation
returns to the project generators within the same stratum
(`corpus_spec.json :: _source_allocation`). Arm A is unaffected: its
definition does not change.
