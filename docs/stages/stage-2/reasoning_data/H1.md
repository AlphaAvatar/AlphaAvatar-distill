## 4. H1: the comparison (`plans/comparison_design.json`, a draft)

**Question.** With the same D4 initialization, the same recovery objective and
a pre-defined matched budget, does replacing corpus_v2 with a verified
teacher-native reasoning corpus improve *actual reasoning correctness* in the
student's own generations?

It is a treatment comparison of two whole data schemes, not a test of a single
filter.

**Arm A: corpus_v2 as it was.**
- The only change is isolation: the 28 sessions that are near-copies of
  held-out prompts take their whole units with them (28 units, 30 sessions);
  a unit is never trained on in part.
- It is **not cleaned**: its wrong targets remain, as they were historically.
- Measured: 3,150 units, 2,960,182 U, 1,459 blocks at 0.355 packing
  efficiency.
- No E1 result stands in for it, because E1 used a PCA initialization and a
  pack that cut traces.

**Arm B: the verified teacher-native corpus.**
- Shares of unique supervised positions: reasoning **0.70** / supporting
  **0.30**, the maintainer's starting point and not a searched optimum.
  - deduction 0.17, induction 0.17, composition 0.17, analogy 0.09,
    interactive 0.10;
  - math 0.12 (0.06 reused verified gsm8k + 0.06 new MATH train), code 0.07,
    evidence reading 0.08 (reused span-verified), answerability 0.03.
- Instruction following is exercised by every task's explicit answer or action
  protocol. Tool calling is omitted. Both are recorded risks.
- **Estimated independent units at 2.96M** (`h1_accounting.json :: quotas_arm_B`):

  | stratum | units |
  | --- | --- |
  | deduction | 136 |
  | induction | 137 |
  | composition | 141 |
  | analogy | 46 |
  | **interactive episodes** | **18** (thin, so the axis is secondary) |
  | reused gsm8k | 151 |
  | MATH | 52 |
  | code | 49 |
  | reading | 380 |
  | answerability | 174 |

- **Families.** The project generators give 32 usable calibration-split
  families: 35 less 3 that compute an evaluation-only rule (R9, below). The
  §8 sources add 23 modules if approved; none computes an evaluation rule, and
  7 share a primitive with one (declared review).

**Quality** (`aadistill.data.target_quality` v2). Every candidate keeps four
different questions in four records, and none is read as more than it shows:
- **answer** -- against an independent gold, with the check's scope recorded:
  the generator's gold (battery protocol v2), the human math gold, the span
  gold, the environment's goal on replay, or the declared tests
  (`aadistill.data.code_exec`: a pass means the declared tests ran and
  passed, not full semantic correctness);
- **text consistency** (observation) -- whether the reasoning restates the
  final answer. Textual agreement only. A different value boxed in the
  reasoning is noted, never called a contradiction: it may be an intermediate;
- **steps** -- intermediate-step verification, set only by a check that reads
  the steps against the task. The project's families have none, so their steps
  are `not_assessed`. PrOntoQA's reference-proof check (every conclusion
  stated, none negated) is the one available step check; a pass is `partial`,
  never `verified`;
- **action legality** (observation) -- every action of an episode legal on
  replay. It says nothing about the natural-language reasoning; an illegal
  action rejects the episode.

On the Stage-0 teacher records: 571 of 672 accepted; static answer-correct
traces restate their answer in 497 cases and not in 58; 68 episodes are all
legal, 4 not; steps are `not_assessed` for all 672 (`audit/asset_audit.json`).
A sampled independent review per family is part of the protocol. Ambiguity and
solvability come from the generators' construction (induction keeps an
instance only when every consistent rule agrees on the query; deduction
redraws unsatisfiable seeds; the audited v2 roster).

**Isolation** (`isolation_rules.json` v2, `isolation_check.check_pool`). Each
rule shows only its own check, and the report says so:
- **R0** provenance: a registered, trainable source and the fields its kind
  needs (a candidate module, family and task type for an external generator).
  Missing information is a violation, never "no conflict found";
- R1 held-out keys; R2 13-gram near-copies; R3 rule families; R4
  evaluation-only generators and their task types; R5 shared-generator seed
  range; R6 source splits;
- **R7** ARC-AGI: ARC-lineage sources and modules refused, and every grid in a
  prompt or gold fingerprinted against ARC-AGI-1's 6,887 training and
  evaluation grids (hashes only, `data/.../isolation/arc_grid_index.json`);
- **R9** mechanism equivalence, by execution: every calibration family's rule
  run against every held-out rule of its domain on 400 seeded inputs.
  `str.caesar`, `str.double_last` and `str.duplicate_each` compute the
  evaluation-only letter-analogy rules `succ_all`, `double_last` and
  `double_all`, so they are not drawn for training. Families without
  tabulated rules and every external module are covered by the declared review
  in `external_modules.json :: mechanism`, which is not an execution check.

`train_tasks_v2` (1,425 tasks, 32 families, sized for 2.96M + reserve)
passes R0–R9 and repeats no Stage-0 or eval instance. `train_tasks_v1` (2,517,
built for the earlier 5.5M spec) fails R9 on 117 items and is superseded.

**Matched budget** (`h1_accounting.json` v2). Every figure carries its kind:
A's pack is **measured**, B's is **estimated** until it exists, E and steps
are **planned**, FLOPs are **modeled**, and runtime rates are **measured** on
earlier runs (`cost_forecast.json`).
- **The rule is fixed now** (`aadistill.training.accounting.match_schedule`):
  the pack with fewer blocks keeps 2 blocks per step; T is searched within
  ±10% of its 3-epoch step count so that every pack's passes stay closest to
  3; each pack takes the integer blocks per step nearest to 3 × blocks / T;
  both run exactly T steps (one learning-rate schedule).
- **Today, provisional** (B estimated): T = 625; A 7 blocks per step (2.9986
  passes), B 2 (3.0048). U ratio 1.0001, planned E 0.9981, steps 1.000,
  supervised per step 0.998. **C is not matched:** A executes 1.28× the
  positions and 1.22× the FLOPs, because its prompts are context.
- **Exact per seed** (A, the trainer's own seeded block stream): E =
  8,873,709 and 8,879,186 for the two seeds. B's exists only with its pack.
- **KD positions per pass** (`kd_scope all`): A prompt 1.28M / reasoning
  2.57M / answer 0.39M (30% / 60% / 9%); B (estimated) 0.35M / 2.63M / 0.33M
  (11% / 79% / 10%).
- 7/2 and T = 625 are not frozen. On B's real pack
  (`h1_accounting --pack-b`), the same rule sets T and blocks per step, the
  exact per-seed U/E/steps of both arms are recomputed, the cost forecast is
  rerun, and only then is the protocol frozen.

Under the frozen config, A would get 3.5× the steps and compute at 0.29× the
supervision per step.

**Schedule.** From the rule on B's real pack; today's provisional values are
T 625, warm-up 31, eval every 78, save every 312. The 0.86M recipe's 1,023
steps are not reused.

**Counting rules:**
- one trace per task;
- repeated context is computed, never counted in U;
- reasoning and answer positions are reported separately.

**Recovery: frozen.**
- CE 0.25 + KD 1.0, T = 1, `kd_scope: all`, full-vocabulary forward KL.
- Same trainable set, AdamW 5e-5, fp32 + bf16 autocast, thinking protocol and
  8,192 context.
- Not introduced: TIP, another KL direction, top-k KD (D1's Top-200 is an
  initialization scoring protocol), hidden or span alignment, loss
  reweighting, student-forced or on-policy training.

**Evaluation.** Uses eval-set-1, frozen identity 2.
- Reported, each separately: every fluid axis; episodes; **both generator
  tiers** (unseen format 190 + 48; unseen rule 380 + 96); supporting units;
  guard rails; usable rollout and its components; CE and KL as diagnostics.
- Diagnostic chain: usable → submitted in protocol → correct → correct on the
  unseen-format tier. The first two alone are not transfer.

**Statistics, fixed before any result is read** (`h1_statistics.py`,
validated on synthetic outcomes).
- **Primary:** static correctness B − A. Per item, d = mean over the two seeds
  of (B correct − A correct): an item is one unit of measurement. The
  statistic is the item-weighted mean.
- **Interval:** two-sided 95% percentile, rule-family cluster bootstrap
  stratified by axis, 10,000 resamples, bootstrap seed 20261022. It covers
  evaluation sampling, not seed variation.
- **Seeds:** each seed's point estimate is reported, and every directional
  label needs both seeds on its side.
- **Resolution:** an interval supports equivalence or the exclusion of a gain
  only with at least 10 discordant (item, seed) pairs in at least 5 clusters
  and a non-degenerate bootstrap. All-zero or sparse successes give [0, 0] or
  a near-empty interval; that says neither arm solved the items, not that the
  arms are equal.
- **Floor:** an arm below 2% correct is at the floor.
- **Labels:** `NOT_RESOLVED` (unresolved, or both arms at the floor: `FLOOR`)
  -> `GO` (interval wholly above +0.05 and both seeds above) -> `REVERSED` ->
  `NO_GO` (inside ±0.05, both seeds inside, and **neither arm at the floor**)
  -> `INCONCLUSIVE`. A one-arm floor is flagged beside any label.
- Axis contrasts use the same rule (SESOI 0.08) with Holm over the axes; the
  rest is descriptive. Old A does not have to leave the floor before H1 runs.

**Steps.** All four formal units run once launched. A single-seed diagnostic
is allowed but is not a confirmation. If B is fully at the floor after
reasonable diagnostics, the next study is H3, not a larger ladder.

**What the audit rests on.** A primary-source desk check of all 8 repos, plus

- **Isolation:** the 305 sampled candidate instances pass R1 and R2 against
  eval-set-1, with 0 key overlaps and 0 13-gram near-duplicates
  (`audit/external_source_samples.json`).
- **Isolation, all rules (2026-10-22):** the same samples pass R0, R4 and R7
  too; an export from a freshly pinned isolated environment (176 rows, 22
  whitelisted modules) became 171 tasks that pass R0–R9
  (`audit/external_tasks_validation.json`).
- **Code verifier:** calibrated on MBPP's human reference solutions, inside the
  same sandbox teacher code will run in. It passes 473/474, and rejects 453 of
  474 "return None" mutants (`audit/code_verifier_check.json`). A pass means
  the declared tests ran and passed.

**Policies that apply to every external source:**
- **A library score is never the verdict.**
  - Wrong answers score 0.84–0.999 in several Reasoning Gym modules.
  - Five Reasoning Gym scorers evaluate the answer text as Python, so they
    never see teacher output.
  - Each module therefore gets a project-side exact or validity check.
- **Instances are generated once and stored.** Every seed is pinned per
  (source, module, level), each entry runs in a fresh process, and the hash
  seed is pinned and checked. (Correction, 2026-10-22: the first 176-row sample
  was NOT hash-seed pinned -- ``-I`` implies ``-E``, which ignores
  ``PYTHONHASHSEED`` -- and two reasoning_core modules depend on it; the
  exporter now runs each child without ``-E`` and refuses an unpinned seed.)
  DeepMind Mathematics' composed modules reorder sub-statements between
  same-seed runs, so the export file's sha256 is the instances' identity.
  A library item that does not return within 60 s is skipped and reported
  (reasoning_gym `bf` at difficulty 3 hangs on some seeds).
- **Reference proofs and traces only verify.** They never enter a prompt or a
  target, and the external answers are never the teacher's target.

**Counting rules.**
- One mechanism found in two libraries counts as one family.
- Several teacher traces of one prompt count as one task.
- Static planning (Reasoning Core `planning`, Reasoning Gym sokoban /
  rush_hour) is never counted as interactive.

**Interactive coverage is insufficient, and is reported rather than filled.**
- The only interactive training source is the project's own environments:
  hidden_buttons (1 calibration family) and probe_function (2).
- That is 3 families, about 18 accepted episodes at 2.96M.
- No external source supplies a real action → observation → feedback loop.
- New seeds cannot turn evaluation families into training ones.
- Closing the gap needs new training-only environments: $0 engineering, and a
  maintainer decision.

**No silent fallback.** Each corpus B can be cut from is a named variant
(`corpus_spec.json :: variants`): `stage2.reasoning_master@v1` (the proposed
scheme, third-party generators included) and
`stage2.reasoning_master@v1-project-only` (no third-party generator). Dropping
a source means choosing the other variant, which carries its own id. On
2026-10-22 the maintainer chose `@v1` (`corpus_spec.json :: chosen_variant`)
and admitted its 11 sources (`sources.json :: approved_for_h1`, with an
`approval` stating it is design, not spending); `generation_plan` and
`build_arm_b` refuse any other variant. Arm A is unaffected: its definition
does not change.

**Third-party isolation.** The libraries and the data they bundle (arckit's
ARC copies included) live only in a pinned virtual environment.
`external_export.py` runs there with `-I` and imports only the modules on the
whitelist `external_tasks.py` writes from the candidate rows. The training
build reads the export file by its sha256, never the library. Each module's
declared comparator must accept its own gold and reject a foreign answer
(this caught `dynamic_programming` declared numeric when its gold is a letter
sequence). Since 2026-10-22 every candidate module has a usable verifier: a
comparator, or a project checker (`checkers.py`: n_queens and tower_of_hanoi
by validity and simulation, planning by closed-world STRIPS simulation,
logic_derivation step by step against the reference derivation, the composed
mathematics modules by exact rationals, ordered sequences and a polynomial
parser that evaluates nothing). A module without one would be dropped from
the paid list by `generation_plan`; none is today.
