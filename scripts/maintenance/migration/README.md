# Information-architecture migration (2026-10-08)

Maintainer instruction of 2026-10-08: pause D1 before behavioural screening and
migrate the repository's information architecture so that any reader, starting
from a logical owner, can mechanically find **code → live state →
design/evidence → runs → durable artifacts**. D1 does not resume until this
migration is independently reviewed.

This directory holds the migration's declarative move map
(`info_architecture.py`) and this design note. The hash-anchored record of what
moved lives at `logs/maintenance/source-relocations/info-architecture/v1/`
once the migration is complete.

## Principles applied

1. **Owner first, type second.** Directories are owned by a stage, an
   experiment, a family, or a genuinely stage-neutral capability — never
   primarily by artifact type.
2. **One namespace across the three trees.** The same owner maps to
   `scripts/stages/stage-<n>/<exp>`, `logs/stages/stage-<n>/<exp>`,
   `artifacts/stages/stage-<n>/<exp>`; families to
   `stages/stage-<n>/families/<family>` in all three.
3. **Cross-experiment ≠ shared.** The D-series family is Stage-1 property:
   `stages/stage-1/families/d_series/`. `shared/` keeps only genuinely
   stage-neutral material.
4. **Live state has one authoritative owner.** Active experiments/families get
   a derived `current.json`; historical analyses carry explicit
   `record_role` / `live_state` fields so they cannot masquerade as blockers.
5. **Ownership moves forward; history is never rewritten.** Frozen records keep
   the paths that were true when written; `logs/index.json ::
   historical_paths.map` (longest-prefix resolver, already in production for
   logs) is extended with the scripts and artifacts pairs from this migration.

## Naming deviations from the instruction's sketch

* **Underscores, not hyphens, for owner directories** (`phase_d1`, `d_series`):
  experiment directories are importable Python packages (`stages.phase_d1`),
  and the whole existing `logs/stages/` tree already uses underscores. The
  mechanical cross-tree mapping matters more than the glyph.
* **Script basenames are preserved** (`autoinit_d1_launch.py` stays
  `autoinit_d1_launch.py` inside `stages/stage-1/phase_d1/`): renames would
  multiply the string-churn against frozen records for zero navigation gain.

## Package layout after migration

* `scripts/stages/` — package `stages`. Its `__init__.py` extends `__path__`
  over `stage-*` and `stage-*/families` grouping directories, so
  `stages.phase_c1` and `stages.d_series` resolve while the physical tree keeps
  the stage and family levels. One import rename repo-wide:
  `experiments.<pkg>` → `stages.<pkg>` (and `experiments.phase_d_series` →
  `stages.d_series`).
* `scripts/shared/` — package `shared`. The former shared application layer
  (`experiments.calibration`, `run_layout`, …) lives flat here
  (`shared.calibration`); stage-neutral CLI capabilities live in subpackages
  (`shared/data`, `shared/evaluation`, `shared/training`, `shared/rollout`,
  `shared/validation`, `shared/pod`, `shared/preflight`).
* `scripts/maintenance/` — repository tooling: `architecture/` (from
  `scripts/architecture`), `consolidation/` (from `scripts/consolidate`),
  `migration/` (this directory).
* `scripts/conftest.py` — the experiment/shared suite bootstrap (was
  `scripts/experiments/conftest.py`); covers every suite under `scripts/`.
* Moved scripts use package imports (`stages.phase_c1.score_c1_confirmation`,
  `shared.evaluation.score_recovery_search`) instead of flat sibling imports
  resolved through ad-hoc `sys.path` roots.

## Core change (exactly one)

`src/aadistill/governance/closure.py`: the grouping-directory resolution is
generalized from "exactly one intervening level" to "a bounded chain of pure
grouping directories" — a grouping directory is one without `__init__.py`,
which is precisely the `stage-*/families/` case — and `INTERNAL_ROOTS` follows
the package renames. No other `src/aadistill` byte changes; the declaration
obligations this edit creates are enumerated and settled in the same round.

## Frozen material: the rules used

* Frozen source-set declarations (`*_SOURCE_FILES_V*` tuples and their
  recorded digests) are **not** repointed. After the move they stop resolving,
  which `scripts/shared/historical_declarations.py` treats as the designed
  outcome (`requires_resolvable`, `assert_declaration_refuses`).
* Regenerable derived records (`executable_closure.json`, the skip-predicate
  classification, the run index, the stage index, navigation READMEs, the log
  inventory) are regenerated by their own generators, never hand-edited.
* Consumed authorizations, grants, preregistrations, run evidence and
  closeouts are byte-identical before and after. Their internal paths resolve
  through the extended `historical_paths` map.

## Intentional exceptions (stay where they are)

* `logs/shared/analyses/` **pinned** records (`autoinit_program_material` and
  the probe-reuse/pricing/isolation/scoring-audit set): named at hard-coded
  paths by drivers that consumed authorizations identify by digest. The stage
  index rows carry the pin and the reason.
* `artifacts/audit/` — the runtime session-audit namespace constructed by
  `src/aadistill/infrastructure/session_runner.py`. Moving it buys no
  navigation and costs a core edit; documented as an operational namespace.
* Stage-level pipeline-activity scripts (`collect_stage0.py`,
  `init_stage1.py`, `train_stage3.py`, corpus builders, …) stay in shared
  capabilities: their subject is the pipeline, not one experiment, matching
  their `pipeline-activity` classification in the stage index.

## Scientific state: unchanged by construction

D1's design (`logs/stages/stage-1/phase_d1/plans/d1_design.json`), its
`design_hash f9c6688f…`, seeds, arm identities, battery role membership and
digests, scoring rules, SESOI, decision rules, and the D2/D3 protocol are not
touched. D1's launcher/authorization/sweep/preregistration deliberately do not
exist yet, and D1 has no executable-closure snapshot, so no D1-bound identity
is invalidated by moving its executables. The battery bytes and the four
finalists are hash-verified after every physical move against their recorded
digests (`autoinit_d_series_family_manifest.json`;
`post_search_finalist_retention.json`).
